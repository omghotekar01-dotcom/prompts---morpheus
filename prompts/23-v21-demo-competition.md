# MASTER PROMPT #23 — V21: DEMO, COMPETITION, TECHNICAL STORYTELLING & PRESTIGE PACKAGE

Design demonstrations that prove MORPHEUS rather than hiding it behind cinematic UI. A judge should understand problem, mechanism, evidence and novelty hypothesis within minutes.

## Core demo story
Start with one workload whose optimal design changes when access pattern changes. Show declarative MWS; strong baseline; synthesis search; selected composite; generated executable code; correctness verification; measured comparison; then shift workload and show drift/adaptation decision. Label every number predicted or measured.

## Demo modes
90-second elevator; 3-minute hackathon; 7-minute technical; 15-minute research; deep-dive interactive. All use the same verified experiment artifacts and progressively reveal detail.

## Evidence hierarchy
Highest: live reproducible benchmark with manifest. Then previously recorded reproducible experiment. Then model prediction. Lowest: conceptual illustration. UI must never visually blur these categories.

## Failure-safe demo
Prebuild deterministic datasets/artifacts; provide offline local mode; cache only clearly labeled previous results; include reset script and health check; avoid dependency on internet/LLM for core synthesis. Have a recorded backup demonstration, but never present recording as live.

## Judge questions
Prepare concise evidence-based answers for: Why not just choose a hash/tree? What is actually novel? How is search performed? How do you know prediction is accurate? What if workload changes? Is generated code correct? How large is search space? How does this differ from database optimizers/autotuning? What are limitations? What is implemented today?

## Technical poster
One pipeline figure, formal objective, one composite example, Pareto/result chart, adaptation timeline, contribution/limitations box and QR to reproducible repository/artifact. Avoid paragraph walls.

## CV/recruiter package
One-line description, 3 evidence-backed technical bullets, stack, measured result only if real, paper/patent status accurate. Create architecture diagram and 2-minute engineering walkthrough.

## Demo telemetry
Display workload hash, machine, candidate count, search time, selected config, memory, predicted/measured latency and correctness status. Hide irrelevant backend noise.

## Acceptance
A fresh evaluator can clone/run a small demo with documented commands; baseline and MORPHEUS semantics match; result is reproducible within expected benchmark variance; no fake metrics/assets are required.

## Deliverable
Produce scripts/storyboards for all demo lengths, judge Q&A bank, poster structure, pitch deck outline, offline demo harness, failure checklist, CV/project descriptions and reproducibility QR/artifact plan. Prestige should be the consequence of technical proof.
