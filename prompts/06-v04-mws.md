# MASTER PROMPT #6 — V04: MORPHEUS WORKLOAD SPECIFICATION LANGUAGE (MWS)

Design MWS as the versioned declarative contract through which humans, tools and AI describe workload intent without choosing physical structures.

## Core rule
Users describe data, operations, distributions, updates, constraints and objectives. They do not specify "use hash/tree/bitmap" except explicit expert search restrictions.

## Root model
`mws_version`, `metadata`, `dataset`, `workload`, `operations`, `updates`, `constraints`, `objective`; optimizer/experiment/deployment settings may live beside MWS in a project request but remain distinct concepts.

## Dataset
Support record datasets first. Fields: name, canonical type, nullable, unique, estimated cardinality, optional string/bytes lengths, stored-value distribution and access distribution. Derived statistics such as cardinality ratio stay out of raw user input.

## Operations
Initial kinds: point_lookup, equality_filter, range_lookup, prefix_lookup, membership plus insert/delete/modify. Each has a unique name, target field(s), weight or absolute rate and operation-specific metadata such as hit rate/selectivity/prefix length.

## Workload modes
Weighted mode sums active operations to 1; rate mode preserves operations/sec and derives probabilities; optional total-rate mode derives absolute rates from weights. Never silently mix or normalize inconsistent modes.

## Constraints/objectives
Normalize units to bytes/nanoseconds internally. Hard memory/latency/build constraints create feasibility requirements; soft constraints use explicit penalties. Objectives support weighted, Pareto and lexicographic policies with transparent expansion of any presets.

## Validation pipeline
Syntax -> schema -> semantic -> resolution -> capability validation. Error families distinguish malformed document, schema violation, unknown field/reference, unresolved profile, unsupported feature and version mismatch. Valid-but-infeasible is not invalid.

## Assumptions
NL/form import can create drafts, but every inferred critical value is stored in an assumption ledger with source/confidence/confirmation state. No invalid or unresolved high-risk spec reaches optimizer.

## Canonicalization
Store raw and resolved MWS. Resolve defaults/presets/units/references; serialize canonical JSON deterministically; compute semantic hash excluding non-semantic metadata. Version defaults.

## Implementation
Use typed Pydantic/domain models plus generated JSON Schema/OpenAPI/frontend types; semantic rules remain a dedicated validator. YAML parsing must be safe and size/depth limited. Paths/identifiers are sanitized.

## Integration
MWS lowers deterministically into WorkloadIR. Runtime observed workloads create separate immutable snapshots rather than mutating declared MWS.

## Required developer experience
CLI `validate/resolve/hash/diff`; API validation; Monaco schema support; wizard/NL/raw YAML all converge on MWS; pre-synthesis review displays assumptions, operation mix and constraints.

## Alpha exit gate
Versioned schema; YAML+JSON parse; semantic validation; explicit defaults; deterministic resolved hash; golden valid/invalid examples; WorkloadIR lowering; CLI/API validation; no unsupported field silently ignored.
