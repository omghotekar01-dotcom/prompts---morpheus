# MASTER PROMPT #18 — V16: PAPER, PATENT, PRIOR ART & CLAIM DISCIPLINE

Create the publication/IP workflow for MORPHEUS with rigorous separation between invention ideas, prior-art findings, experimental evidence and legally meaningful patent claims. Never claim "first", "novel", "patentable" or "state of the art" without evidence and appropriate professional review.

## Contribution ledger
Maintain atomic candidate contributions: declarative workload language; workload IR; capability algebra; composite physical-design search; hardware-calibrated cost modelling; uncertainty-aware selection; generated executable structures; runtime workload drift/adaptation; active workload elicitation. For each record status: IDEA, IMPLEMENTED, EVALUATED, PRIOR_ART_REVIEWED, CLAIMABLE-CANDIDATE.

## Prior-art workflow
Search scholarly literature, patents and relevant production/open-source systems by component and combinations—not project name alone. Record query, date, source, bibliographic/patent ID, exact relevant concept and difference. Distinguish "not found" from "does not exist".

## Novelty matrix
Rows = MORPHEUS mechanisms; columns = prior systems. Cells cite evidence and classify SAME/PARTIAL/DIFFERENT/UNKNOWN. Identify the narrowest defensible differentiating combination.

## Patent preparation
Before public disclosure, prepare invention disclosure: problem, existing approaches, technical mechanism, architecture, alternative embodiments, inventors/contributions, dates, diagrams and experimental evidence. Patent counsel decides patentability/claims/jurisdiction. Do not use AI prose as legal advice.

## Claim strategy
Prefer technical mechanism claims over marketing outcomes. Enumerate method/system/computer-readable-medium possibilities and dependent embodiments, but mark all as DRAFT FOR COUNSEL. Preserve alternative search algorithms, cost models, primitive libraries, adaptation policies and target languages so implementation details do not unnecessarily narrow the invention disclosure.

## Paper structure
Abstract; motivation; problem formulation; MWS/IR; primitive capability model; cost model; synthesis/search; codegen/correctness; runtime adaptation; implementation; evaluation; related work; limitations/threats; conclusion. Every quantitative claim links to an experiment ID.

## Figures
System pipeline; formal optimization model; candidate composition example; search-space/pruning diagram; predicted-vs-measured calibration; Pareto frontier; performance comparison; ablation; adaptation timeline. Generate figures from data/scripts when quantitative.

## Writing discipline
Never describe planned functionality as implemented. Use "we propose" vs "we implement" vs "we observe" accurately. Avoid inflated adjectives. Report workloads/machines/compiler/repetitions. Include negative cases and limitations.

## Venue strategy
Create venue-fit matrix based on actual contribution maturity: data systems, systems/architecture, software engineering, performance/compilers, workshops/student research. Verify current CFP/deadlines externally at submission time.

## CV/artifact package
Prepare concise project summary, contribution bullets tied to evidence, repository/artifact link, demo, preprint/paper only when real, patent status only using accurate terms (e.g., filed/pending only after filing).

## Deliverable
Create contribution ledger, prior-art database format, novelty matrix, invention-disclosure template, counsel-ready technical appendix, paper outline, claim-to-evidence table, figure plan, artifact checklist and disclosure timeline. Scientific prestige must come from reproducible contribution, not wording.
