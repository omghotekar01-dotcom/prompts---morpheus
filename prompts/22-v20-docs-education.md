# MASTER PROMPT #22 — V20: DOCUMENTATION, EDUCATION, SPECIFICATIONS & KNOWLEDGE SYSTEM

Create documentation that lets a student understand MORPHEUS, an engineer integrate it and a researcher reproduce it without relying on hidden chat history.

## Documentation layers
1. 10-minute quickstart.
2. Concepts: workload specialization, MWS, WorkloadIR, ConfigurationIR, capability algebra, cost model, search, codegen, adaptation.
3. Tutorials with executable examples.
4. Normative specifications for MWS/IR/API.
5. Reference for CLI/API/config/errors.
6. Architecture decision records.
7. Research/reproducibility guide.
8. Contributor/primitive-author guide.

## Single source
Generate API/reference tables from schemas/code where possible. Do not manually duplicate enums/defaults across docs. Every released doc declares compatible MORPHEUS/MWS versions.

## Canonical tutorial
Take one small product-record workload from naive baseline through MWS validation, IR, candidate search, selected composite, generated C++, correctness test, benchmark and explanation. Use real output generated by tests, not invented screenshots/numbers.

## Primitive author guide
Explain capability declaration, cost hooks, parameter schema, memory/build/update model, codegen template/interface, correctness oracle, calibration benchmarks and registration. A new primitive should be addable without editing unrelated optimizer logic.

## Research guide
Explain exact experiment manifests, machine calibration, baseline fairness, seeds, raw data, scripts, prediction-vs-measurement labels and paper reproduction.

## Glossary
Define workload, logical operation, primitive, physical configuration, candidate, feasibility, objective, Pareto dominance, calibration, drift, hysteresis and migration. Keep terminology stable.

## ADRs
Record major choices and alternatives: YAML/MWS, IR boundaries, composition ownership, search strategy, cost-model architecture, generated-code isolation, runtime adaptation policy. ADRs explain why, not merely what.

## Education mode
Provide progressively difficult exercises: choose structures manually; predict tradeoffs; inspect MORPHEUS result; modify workload; observe crossover; enumerate small search space. Useful for DSA education without claiming MORPHEUS replaces learning fundamentals.

## Documentation tests
Run code snippets/examples in CI where practical; link checker; schema example validator; detect stale CLI help. Generated benchmark numbers in docs must carry experiment IDs.

## Deliverable
Build docs information architecture, quickstart, conceptual chapters, normative specs, tutorials, references, ADR template, glossary, contributor guide, research reproduction guide and CI doc tests. The repository itself must contain enough truth to reconstruct the system's design.
